# Единый API действий

Общий реестр действий рабочего пространства для интерфейса, ассистента и WebMCP (`src/lib/action-registry.ts`). Каждое действие объявляет идентификатор, версию, вид (чтение/запись), допустимые роли, признак разрушительности, zod-контракт ввода и функцию выполнения. Реестр проверяет существование действия, роль и ввод до выполнения и возвращает коды ошибок `UNKNOWN_ACTION`, `ACCESS_DENIED`, `INVALID_INPUT`.

Действия не расшифровывают данные сами: вызывающая сторона готовит контекст из уже расшифрованных и авторизованных представлений (строки пациентов, клинические записи для врача, собственные определения анализов, дескриптор рабочего пространства). Чтение использует те же примитивы отбора и расчёта, что экраны (`analyzeCohort`, `compareCohorts`, `availableObservationCodes`); запись идёт только через методы рабочего пространства с их серверной проверкой, CAS-ревизиями и шифруемой офлайн-очередью (`analysis.save` → `workspace.saveAnalysis`).

Подключённые действия: `patients.overview`, `cohort.summarize`, `cohort.compare`, `observations.codes` (врач), `analyses.list`, `analysis.save`. Результаты чтения агрегированные; идентификаторы пациентов не возвращаются. Список анализов ограничен собственными определениями пользователя без критериев и сравнений в выдаче.

## Журнал действий

`src/lib/action-journal.ts` — кольцевой буфер (до 200 записей) вызовов текущей сессии: время, актор (пользователь или ассистент, интерфейс `ui`/`chat`/`webmcp`, идентификатор пользователя, модель), действие, версия, успех, код ошибки и затронутый объём (вид и число, без идентификаторов). Постоянное хранение журнала и серверный аудит подключаются вместе с точками входа чата и WebMCP.

## Границы итерации

- Точки входа ассистента (`/ai`) и WebMCP, а также `/settings/ai` ещё не подключены: реестр пока используется программно и покрыт тестами.
- Запись ограничена собственными определениями анализов; клинические записи, согласия и массовые операции через реестр не выполняются. Разрушительные и массовые действия потребуют явного подтверждения пользователя при подключении.
- Интерфейс продолжает вызывать методы рабочего пространства напрямую; маршрутизация экранов через реестр не требуется, потому что проверки прав уже централизованы в рабочем пространстве.

## Проверки

Unit-тесты `tests/action-registry.test.ts` — контракт списка действий, агрегированный обзор через общие семантики отбора, сравнение когорт без идентификаторов, отказы по роли/неизвестному действию/вводу с записями журнала, выдача собственных анализов без значений, коды наблюдений только для врача, запись через рабочее пространство и `WORKSPACE_LOCKED`; полный контур `npm test`, `npm run lint`, `npm run typecheck`, `npm run fmt:check`, `npm run i18n:check`. Браузерный сценарий не проверялся: действует запрет из AGENTS.md.
