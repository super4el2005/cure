# Единый API действий

Общий реестр действий рабочего пространства для интерфейса, ассистента и WebMCP (`src/lib/action-registry.ts`). Каждое действие объявляет идентификатор, версию, вид (чтение/запись), допустимые роли, признак разрушительности, zod-контракт ввода и функцию выполнения. Реестр проверяет существование действия, роль и ввод до выполнения и возвращает коды ошибок `UNKNOWN_ACTION`, `ACCESS_DENIED`, `INVALID_INPUT`.

Действия не расшифровывают данные сами: вызывающая сторона готовит контекст из уже расшифрованных и авторизованных представлений (строки пациентов, клинические записи для врача, собственные определения анализов, дескриптор рабочего пространства). Чтение использует те же примитивы отбора и расчёта, что экраны (`analyzeCohort`, `compareCohorts`, `availableObservationCodes`); запись идёт только через методы рабочего пространства с их серверной проверкой, CAS-ревизиями и шифруемой офлайн-очередью (`analysis.save` → `workspace.saveAnalysis`).

Подключённые действия: `patients.overview`, `cohort.summarize`, `cohort.compare`, `observations.codes` (врач), `analyses.list`, `analysis.save`. Результаты чтения агрегированные; идентификаторы пациентов не возвращаются. Список анализов ограничен собственными определениями пользователя без критериев и сравнений в выдаче.

## Журнал действий

`src/lib/action-journal.ts` — кольцевой буфер (до 200 записей) вызовов текущей сессии: время, актор (пользователь или ассистент, интерфейс `ui`/`chat`/`webmcp`, идентификатор пользователя, модель), действие, версия, успех, код ошибки и затронутый объём (вид и число, без идентификаторов). Постоянное хранение журнала и серверный аудит подключаются вместе с точкой входа чата.

## Точка входа WebMCP

Пока рабочее пространство пациентов открыто, корневой документ регистрирует действия чтения как инструменты WebMCP (`useWebMcpActions`): `patients_overview`, `cohort_summarize`, `cohort_compare`, `observations_codes`, `analyses_list`. Адаптер `src/lib/webmcp.ts` определяет обе точки черновика API (`document.modelContext` и устаревшую `navigator.modelContext`); без поддержки браузером регистрация молча пропускается, а отказ одного инструмента не мешает остальным. Снятие регистрации — через `AbortSignal` при закрытии пространства или истечении доступа.

Инструменты выполняются через тот же реестр с актором `webmcp` и записью в журнал сессии; замыкания расшифровывают живые коллекции в момент вызова, поэтому данные всегда текущие. Записывающие и разрушительные действия браузерным агентам недоступны: они требуют подтверждения внутри страницы и подключатся отдельно. JSON-схемы ввода строятся из zod-контрактов действий, описания инструментов сообщают агрегированный характер выдачи.

## Границы итерации

- Точка входа ассистента (`/ai`) и `/settings/ai` ещё не подключены; постоянное хранение журнала и серверный аудит придут с ними.
- Через WebMCP доступны только действия чтения; записывающие и разрушительные действия требуют подтверждения внутри страницы и подключатся отдельно. Запись через реестр ограничена собственными определениями анализов; клинические записи, согласия и массовые операции через реестр не выполняются.
- Черновой API WebMCP нестабилен: точка входа уже переезжала между `navigator` и `document`, поэтому адаптер изолирован в `src/lib/webmcp.ts` и покрыт двойным определением. Реальная регистрация в браузере с поддержкой WebMCP агентом не проверялась (запрет AGENTS.md).

## Точка входа AI-чата

Боковой AI-чат (`useShellChat` в корневом документе) выполняет действия реестра через протокол структурированных ответов (`src/lib/chat-actions.ts`). Проводной контракт `/api/ai/chat` сознательно не расширяется: каталог действий и правила передаются префиксом последнего пользовательского сообщения (`protocolMessages`), история остаётся чистой. Модель отвечает либо обычным текстом, либо одним JSON-объектом `{"action":"…","input":{…}}`; извлечение терпимо к ограждениям, но строго по схеме.

Предложенные моделью действия проходят тот же реестр с актором `chat`, именем провайдера в поле модели и записью в журнал сессии: неизвестные идентификаторы, чужие роли и невалидный ввод отклоняются кодами реестра. Действия чтения выполняются сразу и показывают карточку с агрегированным JSON-результатом; действия записи (сейчас только `analysis.save`) показывают предварительный просмотр ввода и выполняются только после явного подтверждения пользователя кнопкой, отмена фиксируется в карточке. При закрытом рабочем пространстве каталог не объявляется, а предложенное действие завершается карточкой `WORKSPACE_LOCKED`.

Границы: многошаговые планы и повторная передача результата модели для пересказа не подключены — результат показывается карточкой; диалог по-прежнему хранится только в памяти вкладки; провайдер по умолчанию — GigaChat, переключение провайдера чата и `/settings/ai` не подключены.

## Проверки

Unit-тесты `tests/action-registry.test.ts` — контракт списка действий, агрегированный обзор через общие семантики отбора, сравнение когорт без идентификаторов, отказы по роли/неизвестному действию/вводу с записями журнала, выдача собственных анализов без значений, коды наблюдений только для врача, запись через рабочее пространство и `WORKSPACE_LOCKED`; `tests/webmcp-actions.test.ts` — состав инструментов только для чтения, имена и JSON-схемы, выполнение через реестр с актором `webmcp` и журналом, регистрация с AbortSignal и устойчивость к отказу одного инструмента; `tests/chat-actions.test.ts` — извлечение протокольного JSON (строгий, ограждённый, встроенный), отклонение прозы и битых форм, каталог и запрет действий при закрытом пространстве, обёртка только последнего сообщения; полный контур `npm test`, `npm run lint`, `npm run typecheck`, `npm run fmt:check`, `npm run i18n:check`. Браузерный сценарий не проверялся: действует запрет из AGENTS.md.
