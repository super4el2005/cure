# Наблюдаемость: Sentry + Vercel

## Подключение

1. В [Vercel Marketplace → Sentry](https://vercel.com/marketplace/sentry/sentry) установите интеграцию для проекта Cure. Создайте организацию и один проект Sentry для JavaScript / TanStack Start. Browser и Node используют один DSN и разные имена окружений.
2. В Vercel → Settings → Environment Variables добавьте для Production и Preview:

   | Переменная          | Значение                                                                                    |
   | ------------------- | ------------------------------------------------------------------------------------------- |
   | `PUBLIC_SENTRY_DSN` | Необязательное переопределение DSN браузера; по умолчанию используется `SENTRY_DSN`         |
   | `SENTRY_DSN`        | DSN для Node runtime и браузера при сборке                                                  |
   | `SENTRY_ORG`        | Slug организации                                                                            |
   | `SENTRY_PROJECT`    | Slug проекта                                                                                |
   | `SENTRY_AUTH_TOKEN` | Приватный organization integration token для загрузки sourcemaps; не публиковать в frontend |

   Используйте токен загрузки sourcemaps, предложенный Sentry; обычно нужны `project:releases` и `org:read`. Значения для локальной разработки можно добавить в `.env.local`. Для browser DSN требуется пересборка.

Интеграция может добавить `SENTRY_OTLP_TRACES_URL`, `SENTRY_PUBLIC_KEY` и `SENTRY_VERCEL_LOG_DRAIN_URL`. Сохраните их в настройках Vercel. SDK приложения использует `SENTRY_DSN`: эти адреса не нужно передавать в браузер или подставлять вместо DSN. Само наличие переменных не подтверждает, что drains подключены; проверьте их статус в интеграции. `SENTRY_AUTH_TOKEN` нужен для загрузки sourcemaps и не публикуется через `source.define`. Не добавляйте общий префикс `SENTRY_` в публичные переменные сборщика.

3. Сделайте Redeploy. Release определяется из `VERCEL_GIT_COMMIT_SHA`, окружение из `VERCEL_ENV`. Вне Vercel задайте `SENTRY_RELEASE` при сборке и запуске одинаковым значением.
4. В Sentry проверьте Issues, Logs, Traces и Metrics. Для каждой версии при наличии трёх build credentials загружаются скрытые sourcemaps клиента и сервера; после загрузки `.map` удаляются из артефактов. Не включайте игнорирование ошибок загрузки sourcemaps.
5. Если тариф и права Vercel позволяют, подключите в интеграции Sentry **Vercel Logs / Traces drains**. Это отдельная настройка: SDK сам не включает drains. Они дополняют SDK событиями платформы, включая ошибки запуска функции до загрузки приложения. Настройте фильтры и доступ к данным платформы отдельно: SDK-фильтры Cure не обрабатывают drains.
6. В Sentry создайте уведомления для новых production Issues, роста ошибок и операций с `app.outcome=error`, особенно `app.code=PERSISTENCE_FAILED`. Проверьте адресатов и доставку тестовым уведомлением в интерфейсе Sentry.

Без DSN приложение работает, облачная доставка выключена. Подключение аккаунта, drains и оповещений требует действий владельца Vercel/Sentry и пока не выполнено.

## Что собирается

- Все завершения мутаций TanStack Query: вход/выход, язык, счётчик, настройки AI, управление ключом (только факт операции), проверка подключения, поиск и сохранение справочника, установка PWA. Каталог имён находится в `src/observability/policy.ts`.
- Навигация, неудачные запросы TanStack Query, сбои инициализации localStorage и регистрации service worker.
- Ошибки рендера маршрутов, общий React ErrorBoundary, восстановимые/необработанные ошибки React и стандартные глобальные ошибки браузера/Node через SDK.
- Серверные ответы 5xx и выброшенные исключения; безопасный код ошибки и `X-Request-Id` связывают ответ с событием. Ответы 4xx учитываются как отклонённые операции, без создания Issue.
- Логи операций и счётчик/длительность операций. Трассы выбираются с вероятностью 20%; ошибки и события операций не используют этот sampling. Лимиты и квоты Sentry всё равно действуют.

Общий код находится в `src/observability`; интеграция — в entrypoints и общих cache callbacks, а не в обработчиках каждой кнопки. Новым мутациям достаточно имени в общем каталоге. Произвольные клики по DOM и ввод полей не записываются; Session Replay отключён.

## Данные и офлайн

Перед отправкой SDK удаляет тела запросов, cookies, заголовки, пользователя, query-параметры, неизвестные атрибуты, исходные сообщения ошибок и DOM/console/network breadcrumbs. Остаются безопасные коды, статусы, фиксированные операции и нормализованные маршруты. Stack frames и debug IDs нужны для sourcemaps. Не передавайте персональные данные в имена файлов исходников.

Медицинские запросы, диагнозы из поиска, тексты AI, ключи API и содержимое форм не являются полями телеметрии. Автоматический захват AI input/output отключён. Только фиксированное `app.operation` разрешено в Sentry Logs; `console.log` не является API наблюдаемости приложения.

Очищенная телеметрия браузера может сохраняться стандартным Sentry offline transport в IndexedDB (`cure-observability`, максимум 30 envelopes). Доставка после восстановления связи зависит от доступности IndexedDB, сети и квоты Sentry; потеря событий возможна. Это не очередь пользовательских изменений TanStack DB. Ошибка мониторинга не должна останавливать операции приложения.

## Восстановление и границы

Ошибки маршрутов показывают стандартный Mantine экран с повтором и перезагрузкой; глобальный ErrorBoundary обрабатывает ошибки вне маршрута. Сохранённые данные не очищаются. Query повторяет только временные ошибки чтения, максимум два раза. Мутации автоматически не повторяются; Axios ограничен таймаутом 90 секунд. Необработанная серверная ошибка возвращает обезличенный JSON 500.

Нельзя гарантировать восстановление при OOM, завершении процесса платформой, недоступности CDN или повреждении браузерного хранилища. До загрузки JS React boundary не работает. Внутренние ошибки Convex не попадают автоматически в Vercel drains: приложение видит ошибки обращений к Convex, а экспорт собственных логов Convex нужно отдельно подключить к выбранному облачному приёмнику. Полное покрытие внутренних функций Convex этой настройкой не заявляется.

## Проверка после подключения

Выполняет пользователь: открыть приложение, выполнить поиск, поменять язык, проверить навигацию; увидеть операции в Sentry Logs. Проверить неудачный поиск/ошибку провайдера и сопоставить `X-Request-Id` с событием. В DevTools выключить сеть, убедиться в доступности сохранённых данных, включить сеть и проверить доставку очереди SDK. Проверить отсутствие введённых значений в raw event, breadcrumbs и span attributes. Сопоставить release и читаемый стек с загруженными sourcemaps.

Агент не запускает серверы и не открывает браузер. Проверки пользовательского интерфейса и фактическая доставка в облако до подключения не выполнены.
