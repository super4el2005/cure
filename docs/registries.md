# Реестровые формы и данные регистра

## Что

Конструктор форм исследования (`/d/projects/:id/forms`, `/m/projects/:id/forms`) дополнен реестровой настройкой версии: код регистра и список показателей — вопросов, значения которых сопоставляются между наблюдениями одного пациента. Настройка хранится в неизменяемой версии определения (`definition.registry`) и проходит ту же серверную проверку `formDefinitionSchema`, что и остальное определение. Идентификаторы показателей обязаны ссылаться на вопросы той же версии; дубликаты и невалидный код отклоняются.

Страница данных регистра (`/d/registries/:id`, `/m/registries/:id`, где `:id` — идентификатор семейства формы) доступна из списка шаблонов проекта для версий с реестровой настройкой. Страница работает в открытом клиническом пространстве врача и показывает окончательные ответы по семейству формы в хронологии каждого пациента: матрица «показатель × дата наблюдения» повторных измерений.

Под каждой таблицей фиксируется происхождение каждого наблюдения: источник (форма и её версия), автор записи, время изменения и способ получения. В текущей итерации способ один — ручной ввод врачом.

## Автозаполнение из клинической карты

Для числового показателя регистра в конструкторе можно указать код обследования. При создании нового ответа по такой форме значение подставляется из последнего обследования пациента с этим кодом (по дате наблюдения, при равенстве — по времени изменения; удалённые записи и записи без числового значения не участвуют). Подстановка выполняется только при создании нового ответа и не меняет существующие. Врач проверяет и при необходимости исправляет подставленное значение перед сохранением, поэтому способ получения остаётся ручным вводом врачом; отдельная отметка автозаполнения в происхождении этой итерацией не хранится.

## Доступ

- Настройка регистра в конструкторе — владелец и координатор проекта, как для любой версии шаблона.
- Данные регистра с личными данными — врач в открытом клиническом пространстве своей организации; ввод и исправление значений выполняются в карте пациента на странице опросников.
- Обезличенное чтение — активный участник проекта с членством в организации клиники. Сервер заново проверяет на каждое чтение, что последнее решение о включении участника в этот проект — «включён» или «завершил» и что согласие на участие действует сегодня. Ответ возвращает только показатели регистра: имена, примечания, авторы записей, идентификаторы записей и ответы вне показателей не покидают строки клиники. Наблюдения одного участника сопоставляются между визитами по коду участника — детерминированному псевдониму поверх случайных идентификаторов. Чтение выполняется только по сети и не сохраняется на устройстве.
- Запросы на уточнение данных — активный участник проекта создаёт запрос к конкретному обезличенному наблюдению; врач организации клиники отвечает или отклоняет.

## Запросы на уточнение данных

Из обезличенного просмотра участник проекта может запросить уточнение по конкретному наблюдению: сервер проверяет, что указанное псевдонимом наблюдение существует и относится к участнику с действующим согласием на участие. Запрос хранит только псевдонимные указатели (код участника, дата, версия формы, необязательный показатель) и текст вопроса; личные данные в нём отсутствуют. Повторная отправка с тем же идентификатором возвращает исходный запрос без дубля.

Врач видит запросы на странице регистра своей организации: код участника сопоставляется с пациентом локально, в открытом клиническом пространстве. Ответ или отклонение фиксирует авторство и время; повторное решение по закрытому запросу не меняет исходный статус. Запрос не даёт исследователю права изменять карту пациента — ответом является только текст врача; исправление данных выполняется отдельно в карте пациента.

Запросы — это коммуникация, а не клинические записи: они работают только по сети и не входят в офлайн-очередь.

## Границы

- Колонки показателей задаёт последняя версия семейства; значения каждого наблюдения читаются из снимка определения своей версии, поэтому старые ответы остаются интерпретируемыми после смены вариантов.
- Учитываются только окончательные ответы; черновики в хронологию не входят.
- Согласие пациента на пол и диагнозы не открывает данные регистра исследователю: обезличенное чтение опирается на отдельное согласие на участие в конкретном исследовании, а не на общие категории карты.
- Шаблон должен хотя бы раз синхронизироваться с сервером в исследовательском пространстве; без этого страница сообщает, что регистр не найден.
